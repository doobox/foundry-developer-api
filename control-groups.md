<h1>Reusable control groups</h1>
<p class="lede">Add a coordinated set of controls, CSS and optional markup maintained by Foundry. Control groups are built from the same public controls, visibility expressions and template features available to developer-authored parts.</p>

<p>Declare <code>controlGroups</code> beside <code>controls</code>. Their generated controls participate in responsive values, template access, validation and Inspector grouping exactly like controls declared directly by the part.</p>

```xml
<key>minimumAPIVersion</key><integer>1</integer>
<key>controlGroups</key>
<array>
    <dict>
        <key>type</key><string>background</string>
    </dict>
</array>
```

<p>A declared control group must also be placed explicitly in the primary HTML template. Put its attribute macro on exactly one element:</p>

```html
<section class="hero {{ part.class }}" {{ part.attributes }}>
    <div class="hero__background" {{ controlGroup.background }}>
        {{ childArea("content") }}
    </div>
</section>
```

<p>Foundry reports a validation error when the macro is missing, repeated, used without its matching control-group declaration, or used outside the primary HTML template. There is no implicit root placement.</p>

<h2>Background</h2>
<p>The <code>background</code> group can add Static and Hover configurations for colour, image, linear/radial/conic gradient and video backgrounds. Image controls use the standard image picker and drag-and-drop behaviour. Static values remain active while Hover values are edited and are replaced only while the element carrying <code>{{ controlGroup.background }}</code> matches <code>:hover</code>.</p>

<p>The macro renders the private marker used by Foundry’s scoped CSS and identifies where conditional video elements are inserted. The developer chooses the target element; Foundry manages the implementation. Generated values remain available as <code>control.background…</code> values. Controls hidden by the group’s <code>visibleWhen</code> expressions retain their stored values and remain available to templates.</p>

<p>When a video is selected, Foundry generates one still poster frame for the project asset. The editing canvas receives only that image and never loads the video asset. Preview and published output use a separately exported poster image while the muted, looping video loads and begins playback.</p>

<h2>Choose the capabilities</h2>
<p>Use <code>styles</code> and <code>states</code> when a part needs only part of the Background group. Foundry creates only the selected controls, CSS and conditional markup.</p>

```xml
<key>controlGroups</key>
<array>
    <dict>
        <key>type</key><string>background</string>
        <key>styles</key>
        <array>
            <string>colour</string>
            <string>image</string>
        </array>
        <key>states</key>
        <array>
            <string>static</string>
        </array>
    </dict>
</array>
```

<section class="key-reference"><h3><code>type</code></h3>
<div class="key-meta"><span>String</span><span>Required</span><span><code>background</code></span></div>
<p>Selects the Foundry-maintained Background control group.</p></section>

<section class="key-reference"><h3><code>styles</code></h3>
<div class="key-meta"><span>Array of strings</span><span>Optional</span><span>Default: all styles</span></div>
<p>Selects the background styles the Inspector offers. Accepted values are <code>colour</code>, <code>image</code>, <code>gradient</code> and <code>video</code>. The array must contain at least one unique value. Its first value becomes the initial Static style. When omitted, Foundry includes every style.</p></section>

<section class="key-reference"><h3><code>states</code></h3>
<div class="key-meta"><span>Array of strings</span><span>Optional</span><span>Default: <code>static</code> and <code>hover</code></span></div>
<p>Selects the states the Inspector offers. Accepted values are <code>static</code> and <code>hover</code>. The array must contain <code>static</code>; add <code>hover</code> to include the separate Hover controls and <code>:hover</code> output. Use only <code>static</code> when the part has no hover styling.</p></section>

<h2>Reading Background values</h2>
<p>Every value generated by the selected Background capabilities is available individually through the normal <code>control</code> template namespace. Foundry resolves responsive values for the current breakpoint before exposing them to the template.</p>

```html
{{ if control.backgroundStyle == "image" }}
    <span>{{ control.backgroundImage }}</span>
{{ endif }}

{{ if control.backgroundHoverStyle == "gradient" }}
    <span>{{ control.backgroundHoverGradientType }}</span>
{{ endif }}
```

<p>The group applies the selected background automatically. Read these values when a part needs additional conditional markup or styling. A control hidden by <code>visibleWhen</code> still retains and returns its value.</p>

<h3>Hover values</h3>

<li><code>control.backgroundHoverColor</code></li>

<li><code>control.backgroundHoverGradientTo</code></li>

<li><code>control.backgroundHoverVideoAspectRatio</code></li>

<p>Only values belonging to selected styles and states are generated. Generated values are responsive except <code>backgroundMode</code>, video selections and their posters. A responsive background style can reveal or hide video, but the selected video remains the same at every breakpoint.</p>

<h2>Combining groups and custom controls</h2>
<p>A part may declare ordinary <code>controls</code> and <code>controlGroups</code> together. The generated Background IDs listed above are reserved by the group, so custom control IDs must not duplicate them. Foundry validates group-generated controls as part of the complete manifest.</p>
