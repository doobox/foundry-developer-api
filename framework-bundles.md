<p class="eyebrow">Framework interchange</p>
<h1>Framework bundles</h1>
<p class="lede">Foundry imports and exports reusable framework settings as self-contained <code>.foundryframework</code> bundles, including their preview and bundled font resources.</p>
<p>New frameworks start from the bundled System UI defaults and require a title and supplied image. User-created and imported frameworks are editable without a developer preference; built-in frameworks are read-only. Update Framework saves edited settings into the reusable framework. Edit Framework changes only its title and artwork.</p>
<p>Saved frameworks include only the fixed framework colour palettes: Page, Surface, Text, Muted, Brand, Accent and Links. Custom colour palettes belong to the project and are not included in the bundle. They remain in the project when creating, updating or switching frameworks. Matching names do not override another palette. Standard colour palettes are supplied by Foundry and are not bundled.</p>
<h2>Bundle structure</h2>

<div markdown="1">

```text
Example.foundryframework/
└── Contents/
    ├── Info.plist
    └── Resources/
        ├── framework.json
        ├── preview.png
        └── Assets/
            └── <managed font files>
```

</div>

<p>The current bundle format is version <code>5</code>. Opening a <code>.foundryframework</code> installs it into <code>~/Library/Application Support/Foundry/Frameworks</code>. Built-in frameworks use the same bundle format inside the application.</p>
<h2>Info.plist metadata</h2>
<dl>
<dt>id</dt>
<dd>Required stable UUID.</dd>
<dt>name</dt>
<dd>Required non-empty display name.</dd>
<dt>previewFilename</dt>
<dd>Required filename below <code>Contents/Resources</code>.</dd>
<dt>formatVersion</dt>
<dd>Required integer. The current supported value is <code>5</code>.</dd>
<dt>createdAt / modifiedAt</dt>
<dd>Required plist dates.</dd>
<dt>resources</dt>
<dd>Required array describing bundled project assets and their storage filenames; normally generated by Foundry.</dd>
</dl>
<h2>Preview image</h2>
<p>A valid PNG, JPEG or WebP preview is required, with an extension matching its contents. Tiles use a <code>2:1</code> aspect ratio; <code>1200 × 600</code> pixels is recommended. Other dimensions are accepted and cropped to fill the tile.</p>
<h2>framework.json</h2>
<p>The JSON payload stores seven token groups:</p>
<dl>
<dt>colourPalettes</dt>
<dd>The seven fixed framework palettes, with stable identifiers, one ribbon of shade values, and separate light and dark default shades. Sun and moon markers identify these defaults in the framework editor; both can occupy the same swatch. Project custom palettes and Foundry's standard palettes are excluded.</dd>
<dt>spacing</dt>
<dd>The predefined spacing scale and optional custom spacing tokens.</dd>
<dt>typography</dt>
<dd>Body, heading and monospaced fonts; custom fonts; base size; and the font-size scale with line-height choices.</dd>
<dt>screens</dt>
<dd>Present in the stored format, but breakpoints are project settings, not reusable framework settings. Saved frameworks use the standard screen configuration; applying a framework preserves the project's enabled breakpoints, minimum widths and container width rules.</dd>
<dt>shadows</dt>
<dd>The predefined shadow scale and optional custom shadows.</dd>
<dt>borderWidths</dt>
<dd>The predefined border-width scale. Foundry supplies this scale when loading an older bundle that does not contain it.</dd>
<dt>borderRadii</dt>
<dd>The predefined corner-radius scale. Foundry supplies this scale when loading an older bundle that does not contain it.</dd>
</dl>
<div class="callout warning">
<strong>Use Foundry to author the bundle.</strong> <code>framework.json</code> is a Codable interchange payload rather than a separately versioned third-party authoring API. Export a framework from Foundry to obtain canonical metadata, resource records and font storage names before editing or distributing it.</div>
<h2>Part integration</h2>
<p>Parts do not read <code>framework.json</code> directly. Declare <a href="framework-controls.html">framework-aware controls</a>; Foundry resolves their semantic selections against the active project framework before substituting template values.</p>
